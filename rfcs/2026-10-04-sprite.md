- **相关 RFC**：[基础节点系统](./2026-07-20-node-system.md)、[布局系统](./2026-07-20-layout-system.md)、[多倍图资源适配](./2026-09-30-multi-res-assets.md)

## 摘要

`Sprite` 是绘制位图内容的基础节点：从 `assets/` 加载纹理，按 `area` 裁剪源图区域，可以保持原尺寸绘制，也可以以九宫格方式拉伸到目标尺寸；`alphaHitTest` 让命中测试按纹素透明度进行，图片的透明位置不接收命中。

本文规定 Sprite 的公开属性、尺寸来源、纹理加载与替换的可见行为、两种绘制模式的几何规则、与多倍图资源的关系，以及命中测试的判定与回退语义。

## 背景

Sprite 覆盖背景、立绘、UI 贴图等主要绘制场景。这些场景要求节点能够：整图绘制；裁剪源图的局部区域；把带边框的 UI 贴图拉伸到任意目标尺寸并保持边角不变形；带透明边距或不规则轮廓的图片（立绘、异形按钮）按实际画面参与命中。

节点与渲染器分层、通用属性、绘制顺序与命中遍历由[基础节点系统](./2026-07-20-node-system.md)定义。本文只定义 Sprite 自身的语义；纹理的文件定位、变体选择与像素倍率由[多倍图资源适配](./2026-09-30-multi-res-assets.md)定义。

## 目标

- 定义 Sprite 的全部属性、默认值与 Patch 行为；
- 定义 normal 与 nineslice 的尺寸来源、几何与采样规则；
- 定义纹理异步加载、替换与失败时的可见行为；
- 定义 `alphaHitTest` 的判定规则、回退行为与数据归属；
- 定义 Sprite 与多倍图资源、通用命中能力的组合方式。

## 非目标

- 通用节点属性与命中遍历框架（见基础节点系统 RFC）；
- 纹理资源的文件定位、变体选择、缓存与回收（见多倍图资源适配 RFC）；
- nineslice 模式下的像素级命中：区域经过缩放或重复，逐像素语义待单独设计；
- 其它节点类型（animation、video、editable 等）的像素级命中；
- 可配置的 alpha 阈值（固定为「大于 0 即命中」）；
- 运行期流式纹理（视频帧、逐帧动画）的掩码。

## 公开 API

Rust 侧注册节点类型 `sprite`，Kit 侧以 `<sprite>` intrinsic element 暴露：

```tsx
<sprite src="bg/classroom.png" />
```

Sprite 专有属性：

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `src` | `string` | 必填 | 纹理资源路径，相对 `assets/`；更改时异步替换 |
| `mode` | `"normal" \| "nineslice"` | `"normal"` | 绘制模式 |
| `area` | `[number, number, number, number]` | `[0, 0, 1, 1]` | 源图裁剪区域，纹理内相对坐标 `[x0, y0, x1, y1]` |
| `bounds` | `[number, number, number, number]` | `[0, 0, 0, 0]` | 九宫格边距，相对 `area` 的比例 `[left, top, right, bottom]`，仅 nineslice 使用 |
| `nineSliceMode` | `"stretch" \| "repeat" \| "mirror" \| "blank"` | `"stretch"` | 九宫格中心与边缘的填充方式 |
| `targetWidth` | `number` | `0` | 九宫格目标宽度（舞台单位） |
| `targetHeight` | `number` | `0` | 九宫格目标高度（舞台单位） |
| `alphaHitTest` | `boolean` | `false` | 启用像素级命中判定，仅 normal 模式生效 |

属性更新遵循通用 Patch 语义（Missing 保持现值、Set 写入新值、Reset 恢复默认值），删除属性等价于 Reset。Sprite 同时支持全部通用节点属性。

`bounds` 的四个值取值在 0~1；左右之和与上下之和不应超过 1。

## 尺寸与布局

**normal**：intrinsic size 由纹理与 `area` 决定：

$$
intrinsicWidth=\frac{W}{r}(ax_1-ax_0),\qquad intrinsicHeight=\frac{H}{r}(ay_1-ay_0)
$$

其中 $W$、$H$ 为纹理像素尺寸，$r$ 为像素倍率（多倍图变体，基础图为 1）。纹理未就绪时 intrinsic size 为 $0\times0$，节点在布局中不占位；就绪后取得尺寸。`area` 或纹理变化都会重新计算。

**nineslice**：intrinsic size 等于 `targetWidth × targetHeight`，与纹理尺寸无关；纹理未就绪也按目标尺寸占位。

默认 `Node::measure()` 把 intrinsic size 复制为 layout size；Sprite 不根据子树内容测量。`x/y`、anchor、pivot 与其它变换语义遵循布局 RFC。

## 纹理加载与替换

- `src` 写入后，由渲染准备阶段发起异步加载，文件读取与解码不在渲染路径上；
- 加载期间保留当前纹理继续绘制与命中；新纹理就绪后整体替换，并重算尺寸与绘制数据，替换过程不出现空白帧；
- 纹理按 `(url, kind)` 在资源管理器中去重共享，多个 sprite 引用同一路径只持有一份纹理；不再被引用的资源由周期扫描回收；
- 变体选择遵循多倍图资源适配 RFC：按当前显示倍率选择文件，并用像素倍率把文件像素换算为舞台单位；切换变体不改变画面尺寸；
- 加载失败时记录错误并保留当前纹理；失败的替换不自动重试；
- Sprite 就绪的条件：已有可用纹理、没有待处理的替换、子树就绪。

## 绘制模式

绘制使用单位四边形配合每绘制单元一个实例。普通实例携带节点全局变换、局部矩形、UV 矩形与 tint（含全局不透明度）；平铺实例在其后追加平铺参数（两轴重复次数与 mirror 标志）。片元按 UV 采样后与 tint 相乘，以预乘 alpha 混合输出；采样使用线性过滤与 mipmap，寻址模式为 ClampToEdge。

渲染器持有两条管线，各自声明实例布局：默认管线只插值最终 UV 与 tint，使用不含平铺参数的普通布局，覆盖 normal、nineslice 的 `stretch` 与 `blank`；平铺管线额外插值区域边界与平铺参数，只服务 `repeat` 与 `mirror`，其节点使用宽 16 字节的平铺布局。两条管线共用纹理绑定、四边形与索引缓冲，按节点选择，节点内实例数与绘制次数不变。

每个绘制单元由局部矩形与 UV 矩形描述，顶点位置在两者之间线性插值；两种模式都表达为若干这样的单元。

### normal

单个绘制单元：局部矩形为 `[0, 0, areaW, areaH]`（`area` 的逻辑尺寸），UV 矩形为 `area`。画面尺寸与 intrinsic size 一致，不做缩放。

### nineslice

`bounds` 在 `area` 内把源区域划分为九块：四角、四边与中心。四角区域保持源尺寸，不缩放；上、下边缘区域只在水平方向拉伸，左、右边缘区域只在垂直方向拉伸，中心区域双向拉伸；右侧与底部区域对齐到目标矩形边缘。目标尺寸小于两侧区域之和时，中心区域压缩为 0，右侧与底部区域从左上方向依次排布，绘制范围可能超出目标矩形；左右边距之和达到 1 时中心区域宽度为 0，不参与绘制。

`nineSliceMode` 决定边缘与中心区域如何填充：

| 值 | 行为 |
| --- | --- |
| `stretch` | 拉伸源图案填满区域 |
| `repeat` | 图案按源尺寸重复，充满区域 |
| `mirror` | 同 `repeat`，相邻图案在拉伸轴向上交替翻转 |
| `blank` | 四角与边缘按 `stretch` 绘制，中心区域不绘制 |

平铺保持图案的源尺寸：区域中出现图案的次数等于其被拉伸的倍数，最后一次可能出现不足一个完整图案。平铺的纹素映射在采样层完成，相邻图案交界处的 mip 选择与图案内部一致。四角区域不受填充方式影响，始终按源尺寸绘制。

## 命中测试

### 默认判定

未启用 `alphaHitTest` 时，Sprite 使用通用矩形判定：`content_bounds`，即自身矩形与子树布局边界的并集。包装节点可用通用属性 `hitTestSelf=false` 让出自身命中，把被拒绝的位置交给后面的节点（见基础节点系统 RFC）；Kit 的 Button 等包装组件即以此让出命中。

### alphaHitTest

启用后（且 `mode` 为 `normal`），命中要求位置同时满足：

1. 位于绘制四边形内，即局部坐标落在 `[0, 0, areaW, areaH]`；
2. 对应纹素不透明：按下式定位纹素，alpha 大于 0 即视为命中。

$$
texelX=\operatorname{clamp}(ax_0W+xr,\ 0,\ W-1),\qquad texelY=\operatorname{clamp}(ay_0H+yr,\ 0,\ H-1)
$$

该换算与绘制使用同一组参数，因此命中位置与画面一致，并随多倍图变体的像素倍率自动调整。半透明边缘视为命中，抗锯齿边缘不会漏判；tint 与 opacity 不影响判定。

**掩码数据**：判定数据是挂在纹理资源上的透明度掩码，有两种形态：全不透明（不分配额外内存）或每纹素 1 bit 的位图（透明纹素置位）。掩码在纹理加载、像素仍在 CPU 内存时构建，不使用 GPU 回读，也不额外读取文件；命中判定只是同步的内存查位。掩码先于纹理就绪发布，因此纹理可用时掩码必然存在。掩码随纹理共享与回收，同一张图被多个 sprite 引用时只保存一份；掩码与所选多倍图变体同源，命中位置随画面同步切换。

**回退行为**：

| 情形 | 判定 |
| --- | --- |
| `alphaHitTest` 未启用 | 矩形 |
| `mode` 为 `nineslice` | 矩形 |
| 纹理未就绪或掩码缺失 | 矩形 |
| 位置在绘制四边形之外（含退化 `area`） | 不命中 |

## 已知取舍

- 掩码在纹理加载时构建，所有纹理都会多一次线性扫描；该开销与解码、premultiply 属同一量级；
- 位图只在图片包含透明纹素时分配（1 bit/纹素，2048×2048 约 512 KB），单个透明纹素即触发分配；
- 透明判定只有「全不透明」与「位图」两种粒度，不区分半透明程度；
- 纹理未就绪期间回退矩形判定，与此时画面尚未出现的观感一致；
- nineslice 不做像素级判定，区域经过缩放，没有与纹素一一对应的位置；
- 使用 `repeat` 与 `mirror` 的节点，每个实例比普通节点多一个 vec4（平铺参数）；其余绘制路径不包含这部分实例数据。

## 被否决的方案

### 掩码缓存在节点上

同一张图被多个 sprite 引用时会重复占用内存；替换 `src`、切换变体时每个节点都要各自失效。掩码改挂在纹理资源上，随资源共享与回收。

### 懒构建掩码（首次命中时重读文件并解码）

需要为用到的纹理多付一遍完整读取与解码，还要处理并发去重与状态管理。掩码改为加载时顺带构建，此后命中判定零额外读取。

### 通过 GPU 回读像素

需要管线同步点与异步映射回调，命中路径无法保持同步语义。掩码在 CPU 侧构建，不走回读。

### 保存 alpha 通道的 u8 副本

4 字节/纹素，是 1 bit 位图的 32 倍，而判定只需要二值。

### 用几何重复实现平铺

每个图案块发一个绘制单元：实例数随目标尺寸增长（1920 宽、16 像素图案即 120 个），相邻块之间无法保证采样连续。平铺在采样层完成，实例数不变，交界处的采样连续。

### 把平铺拆成独立的节点类型或 shader

平铺与节点类型不在同一层：`nineslice` 的 `stretch` 与 `blank` 由默认管线绘制，`repeat` 与 `mirror` 由平铺管线绘制。拆出九宫格节点或平铺节点后，每个节点仍要同时持两条管线，一条都减不掉；同时要复制加载、prepare、update、collect_commands 与命中测试整套逻辑，或抽出共享渲染组件再包两个薄节点，间接层比现状更多。一个节点类型持有它需要的多条管线是本仓库的既有形态（blur 渲染器 4 条，shader 渲染器 2 条）。当前实现保持一个 shader 模块、两组 entry point，共享顶点变换与绑定声明。出现下列情况时再考虑拆分：平铺路径获得独立于 sprite 的公开属性或生命周期；第二种节点类型需要平铺采样；采样路径增至三种以上，届时按变体表或宏生成 entry point。

## 测试与验收

覆盖内容：

1. 属性缺省与 Reset：各属性删除后恢复默认；`area`、`mode`、target 变化立即反映到尺寸与绘制；
2. 尺寸：normal 在纹理就绪前后 intrinsic size 从 0 变为 `area` 逻辑尺寸；nineslice 尺寸只取决于 target；
3. 替换：`src` 切换期间旧纹理继续绘制，就绪后无空白帧地切换；
4. 九宫格：四角不变形、边缘单轴缩放、中心双向缩放；目标尺寸不足时的压缩行为；
5. 多倍图：变体切换不改变绘制尺寸，命中位置与画面一致；
6. 命中：开关对比、透明与半透明边缘、纹理未就绪回退、nineslice 回退、同图多节点共享掩码。
